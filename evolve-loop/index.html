CLAUDE CODE MOD

Recall

一个 Claude Code mod。它在你干活的时候把经验记下来，在你需要的时候把这些记录提炼成一份经验插件——装上之后，Claude 在这个项目里就不再从零开始。

2026-10-03 · 名字是占位 · 设计稿，尚未实现

这个 mod 做什么

三件事，都在 Claude Code 内部完成：

做什么什么时候
记在每个 turn 的边界上记下：要做什么、做了什么、环境返回了什么、成没成一直，后台
炼把积累的记录提炼成一份经验插件你敲命令时
用装上之后，在每个会话开头把这份经验交给 Claude每次开新会话

"经验"是一份可读的东西：它知道这个项目的哪些约定、踩过哪些坑、还有哪些没搞清楚。不是一团权重，你随时能打开看。

它提供的命令

命令做什么
/recall从积累的记录产出下一版经验
/recall show看最新一版学到了什么
/recall status现在攒了多少记录、上次产出是什么时候
装上、换版本、回滚，不用这个 mod 的命令——产出物本身就是一个普通插件，用 Claude Code 自带的 /plugin 那套就行。这个 mod 不重复造。

怎么用

1. 装上 mod

> /plugin install recall@<源>

装完就开始记了。不需要开启，也不会问你任何问题。

2. 正常干活

该怎么用 Claude Code 就怎么用。记录在背后进行，不打断、不弹窗。

> /recall status

  已记录 142 条（最早 9 月 20 日）
  还没产出过经验

3. 产出第一版

> /recall

  提炼中…（不阻塞，你可以继续干活）

  ✓ 产出 recall-api-gateway v1
    敲 /recall show 看它学到了什么
> /recall show

  # 它知道的
  · 这个项目的迁移脚本必须先跑 dry-run —— 来自 9/22 那次回滚
  · 配置改动走 PR，不直接改线上 —— 来自 9/28 被拒的那次

  # 它还不确定的
  · 测试超时的阈值是 30s 还是 60s，两次记录不一致
注意最后那段。它会把自己没搞清楚的事情列出来，而不是硬给一个结论。

4. 装上这份经验

> /plugin install recall-api-gateway

从下一个会话开始，Claude 就带着这份经验干活了。

5. 攒一阵子，再产一版

> /recall

  # 这次自动以当前装着的 v1 为起点
  ✓ 产出 recall-api-gateway v2

> /plugin update recall-api-gateway

不满意就不更新，v1 一直在那儿。

它不做什么

  • 不自动装。产出之后等你看过再决定。Claude 学到的也可能是错的，而一条错误的"经验"会被反复应用，还每次都显得有道理。
  • 不打扰你。记录全程不提问、不弹窗、不要求配合。你应该感觉不到它存在。
  • 不猜对错。没把握的事它标注"还不确定"，不硬编一个结论。

什么项目适合

效果取决于能不能判断对错。

场景
合适跑一下就知道成没成的：写代码、跑作业、调用有明确契约的接口
不合适没有客观判据的：这段文案好不好、这个设计合不合理

不合适的那类只能靠猜，而它不猜。
