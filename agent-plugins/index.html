Claude Code 与 Codex 的插件系统14 种组件、进程内运行的 mods，和一个跨厂商标准——两家把"可扩展"做成了两件不同的事

整理于 2026-10-02 · 以官方文档为准 · Claude Code mods 需要 v2.1.287+

一句话对比。Claude Code 把扩展做深：14 种组件，外加一层能进到渲染和事件循环里的 mods。Codex 把扩展做宽：组件种类少，但采用了能跨客户端复用的开放标准。

1 · Claude Code 插件的 14 种组件

一个 plugin 就是一个目录加一份 manifest。manifest 在 .claude-plugin/plugin.json，给插件一个名字；其余组件按约定目录摆放，每一种都可选，一个都不加也是合法插件。

组件路径作用
Manifest.claude-plugin/plugin.json必需。名字、版本、描述、各组件位置的覆盖键
Skillsskills/<name>/SKILL.md描述匹配任务时 Claude 自动加载；也能当 /plugin:name 命令跑。新写的东西都该用它
Commandscommands/*.md旧格式，已被 skills 取代。只建议用来搬迁 .claude/commands/ 里的老文件
Agentsagents/*.md子 agent，自带指令和独立上下文窗口。支持子目录嵌套命名
Hookshooks/hooks.json生命周期触发：shell 命令、HTTP 请求、MCP 工具调用、给模型的 prompt，或一个子 agent
MCP servers.mcp.json给 Claude 加工具
LSP servers.lsp.json语言诊断与代码导航。插件只负责配置连接，不负责装 binary
Workflowsworkflows/*.js一个 meta 块加脚本体，编排多个子 agent，以 /plugin:name 运行
Executablesbin/*插件启用期间进 Bash 工具的 PATH，Claude 可以当普通命令调。排在用户自己的 PATH 之后，盖不掉 git/ls
Monitorsmonitors/monitors.json整个 session 后台跑的 shell 命令，输出作为通知送到 Claude 面前
Channelsmanifest channels + MCP让外部系统（聊天软件之类）把消息发进 session
Settingssettings.json只有 agent 和 subagentStatusLine 两个键生效，其余丢弃
Themesthemes/*.json配色主题，进 /theme 选择器
Output stylesoutput-styles/*.md输出风格，进 /output-style
一个容易踩的坑：插件根目录的 CLAUDE.md 不会被当成项目上下文加载。要在插件里放指令，写成 skill。claude plugin validate 会对这种文件报 CLAUDE.md at the plugin root is not loaded as project context。

2 · 每种组件怎么写

Skills — 新代码的默认选择

my-plugin/
├── .claude-plugin/plugin.json
└── skills/review/SKILL.md
---
description: Reviews a pull request for style and test coverage. Use when asked to review code.
---

Review the changed files. Report style problems first, then missing tests.

加载后 /my-plugin:review 就能跑。命名规则是 /<plugin>:<目录名>；frontmatter 里的 name 只替换最后一段，插件前缀保留。谁能调用（Claude、用户、还是都行）也由 frontmatter 控制。

Agents — 子 agent

---
name: security-reviewer
description: Reviews code changes for security issues. Use after edits to authentication or input handling.
model: sonnet
---

You are a security reviewer. Read the changed files and report injection,
authentication, and secrets-handling risks.

用户可以用 @agent-my-plugin:security-reviewer 显式调用。支持的 frontmatter 字段：name、description、model、effort、maxTurns、tools、disallowedTools、skills、memory、background、omitClaudeMd、isolation（只接受 "worktree"）、color。

被忽略的字段：permissionMode、hooks、mcpServers、initialPrompt。agent 文件没法自己加 hook 或 MCP server——这是故意的权限边界，要加就加到插件层。而且 frontmatter 解析失败时 agent 照样加载，只是所有字段被忽略，描述变成 Agent from my-plugin plugin。这种静默降级只能靠 claude plugin validate 发现。

Hooks

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          { "type": "command",
            "command": "\"${CLAUDE_PLUGIN_ROOT}/scripts/format.sh\"" }
        ]
      }
    ]
  }
}

格式跟 settings.json 里的 hooks 对象一样，所以已有的 settings hook 可以原样抄进来。

LSP / Executables / Monitors

// .lsp.json —— 注意是直接映射，外面不套对象
{ "gopls": { "command": "gopls", "args": ["serve"],
             "extensionToLanguage": { ".go": "go" } } }
// monitors/monitors.json
[ { "name": "error-log", "command": "tail -F ./logs/error.log",
    "description": "Application error log" } ]
claude plugin validate 不读 .lsp.json。任一条目非法整个文件在加载时被跳过，只在 /plugin 的 Errors 标签页里出现 Invalid LSP server config。另外 LSP server 必须把日志打到 stderr——Claude Code 把 stdout 全当协议消息读。

3 · Mods：10 月 1 日发布的那一层

2026-10-01 需要 v2.1.287+ 默认开启

前面十四种组件有个共同点：它们都在 Claude Code 外面。skill 给文本，MCP 给工具，settings hook 跑一个脚本。mod 不一样——它的代码跑在 Claude Code 自己的进程里。

一个 mod 就是一个插件，里面是 JavaScript / TypeScript 写的事件处理器。工具被调用、prompt 被提交、界面某一块要被画出来，Claude Code 就调你的函数；你的函数可以观察它、改写它，或者直接接管。

命名上的混乱，先说清楚：Claude Code 把两种东西都叫 hook。官方文档的约定是——在 mods 相关页面里，"hook" 指 mod 的处理函数，配置在 settings 文件里的那种叫 "settings hook"。

mod 能干别人干不了的事

  • 画界面——transcript 旁边的侧栏（pane），或 prompt 上方的横条（band），带标签页、按钮、输入框
  • 重画 Claude Code 自己的界面——替换或重新配色它自己画的部分：工具调用那一行、spinner、提问对话框
  • 插进一次工具调用或一次请求——把工具调用挂起去问用户一句话、不跑工具直接返回结果、或者把某一次请求发给另一个模型
  • 注册立即执行的命令——一个 /command 直接跑你的函数，不发起 Claude 轮次，甚至能在 Claude 正忙的时候跑
  • hook 之间共享数据——同一个 mod 的 hook 共享文件里的变量，一个记录另一个展示

官方给的四者对比

能改什么工具调用、prompt、命令、轮次、界面绘制事件放不放行、工具调用的参数和结果、给 Claude 加的上下文Claude 知道什么、做什么Claude 有哪些工具

4 · 一个完整的最小 mod

三个文件：

first-mod/
├── .claude-plugin/plugin.json   # 插件 manifest
└── hooks/
    ├── hooks.json               # modules: ["./register.js"]
    └── register.js              # 代码本体（hooks module）

下面是官方的完整 register.js。它数 Claude 调了多少次工具，并把计数显示在 spinner 旁边，效果是 Thinking · tool calls: 3…：

// 计数，被下面两个 hook 共享
let calls = 0

// mod 加载时 Claude Code 调一次
export function register(on) {
  // 每次 Claude 准备用工具时跑
  on('tool.call', async ($, e, next) => {
    calls += 1
    // 请求重绘界面，好让新计数显示出来
    $.ui.invalidate('ui.render')
    // 让工具照常运行
    return next(e)
  })

  // 每次 Claude Code 画 spinner 时跑
  on('ui.render', { component: 'Spinner' }, async ($, e, next) => {
    // 保留 Claude Code 自己的 spinner，在它后面加上计数
    return next({ ...e, props: { ...e.props, suffix: ' · tool calls: ' + calls + '…' } })
  })
}

三个参数值得记：

参数是什么
$mods API。调用要写全命名空间，如 $.fs.read('notes.md')
e事件输入，深度冻结的纯数据。要改就传一份副本给 next
next(e)下一个处理器，middleware 那套。跑完后面的 hook，再跑 Claude Code 自己的行为

另外 next.signal 是事件被放弃时触发的 AbortSignal；next.budget.remainingMs 是这个 hook 还剩多少时间；next.origin 告诉你事件是谁发的（Claude Code 自己是 { plugin: 'engine', tier: 'core' }）。

一个 hook 对事件只有三种处理方式：观察（原样 next(e)）、改写（next({ ...e, text })）、接管（不调 next，直接返回一个对象，比如 { deny: '请用文件工具。' }）。

5 · 事件清单

工具

事件何时触发可以返回
tool.call工具即将运行next(e) / { deny: reason } / { result }
tool.checkClaude Code 决定工具调用是否放行时（在 tool.call 和 PreToolUse 之后）{ decision }：allow/ask/deny
tool.describe每个工具的描述首次发给 Claude 时，各一次{ description }

Prompt 与 Claude 读到的东西

事件何时触发
prompt.submitprompt 被提交。可改写文本、加上下文，或 { drop: reason } 丢弃
prompt.fill / prompt.suggest / prompt.edit文本进入输入框（草稿 / 暗色建议）、用户编辑输入框
prompt.compose / prompt.section渲染 system prompt / 每个命名段落各一次。{ text: null } 可以删掉整段 system prompt
prompt.context / prompt.attachment每个会话首条消息的上下文 / Claude Code 自己加的消息（如 reminder）
skill.promptskill 的文本为 Claude 展开时
attribution.text生成 commit / PR 的署名文本时

轮次、会话、子 agent

事件何时触发
turn.start / turn.step / turn.complete轮次开始 / 每一次发往模型的请求（可改 model、effort）/ 轮次结束
session.start / session.end首个 prompt 之前（每个 mod 一次）/ 会话结束或 /clear、/resume、/branch
session.compact即将压缩对话，可 { skip: reason }
session.send / session.receive与其他 session 或 agent 收发消息
session.append / session.measure每条留存记录写入前 / 每轮之后与用量百分比变化时
agent.offer / agent.spawn子 agent 类型被提供给 Claude（可 { isOffered: false } 藏掉）/ 子 agent 即将启动（可改 model 或拒绝）

界面与其他

事件何时触发
ui.render某个渲染点即将绘制
ui.press / ui.input / ui.selectmod 画的 Button / Input / Select 被使用
ui.focus / ui.scroll / ui.close / ui.message焦点或滚动位置变化 / pane 关闭 / Client 元素回传数据
command.run / command.describe命令即将运行 / 为命令列表描述每个命令
config.set / config.describe/config 某行即将改变（可拒绝）/ 描述每一行
plugin.register另一个 mod 的代码即将加载，e.uses 列出它用到的事件、API 调用、环境变量，可 { refuse: reason } 拒绝它
classic.<Event>每个 settings hook 事件，如 classic.Stop、classic.PostToolUse
每个 mods API 方法本身也是事件。fs.read、model.complete、ui.open 都能被 hook。挂上去就能拦截排在你后面的那些 mod 的调用，返回 { deny: reason } 或 { value }。企业版的策略 mod 就是这么实现的。

# 输出里的 hooks: 和 calls: 两行就是它的能力清单

7 · 限制、内置 mod 与安全

限制值
单个 hook 处理一个事件的执行时间（不含 next 内部）10 秒
全部 session.end hook 合计1.5 秒
$.process.run 超时默认 30 秒，最多 10 分钟
$.model.complete 的 maxTokens默认 1024，最高 64,000
$.fs 单文件读写4 MiB
$.store 总量4 MiB JSON
重绘节流每秒 10 次，可见 pane 与横条 30 次

Claude Code 自己有些功能就是 mod

在 /plugin 的 Installed 标签页下的 Built-in 能看到。cc-plugin-diff 接管了 /diff 并画它的侧栏；cc-plugin-agents-md 负责把 AGENTS.md 当项目指令加载；cc-plugin-sec-default 是保护企业托管配置的守卫。部分源码公开在 anthropics/claude-code 的 mods 目录。

官方的示例 mod 在 claude-code-playground：token-weather（在 prompt 上方画上下文窗口预报）、blast-radius（拦住 rm -rf 或 force push 这类危险命令，展示影响范围并给出继续/取消按钮）、replay-theater（/replay 逐步回放上一轮的文件编辑）。

mod 不在沙箱里。它以你的权限、在 Claude Code 进程内运行，能读写你账号能碰的任何文件、起进程、发网络请求、读环境变量和设置里的 API key、看见你每一条 prompt 和每一次工具调用、在你被问到之前就替你批准工具调用、花你的额度调模型。就算你开了 sandboxing，那只隔离 Claude 跑的 Bash 命令，mod 起的进程在沙箱外面。

唯一画不了的是权限确认框——mod 改不了它给你看的内容。

8 · Codex 的插件

Codex 的插件组件少得多：

  • Skills——可复用的指令包，和 Claude 的 skills 概念一致
  • MCP servers——连 GitHub、Slack、Google Drive 这类外部系统
  • Browser extensions——工作流需要的浏览器能力
  • Hooks——在 Codex runtime 的生命周期点上运行的命令

目录结构：

my-plugin/
├── plugin.json          # Agent Plugins schema
├── mcp.json             # 可选，mcpServers
├── skills/              # 自动发现，manifest 里不用声明
├── assets/
└── hooks/               # 可选

旧版 Codex 兼容路径是 .codex-plugin/plugin.json。OpenAI 专属的东西放在 extensions.com.openai 下面：interface（展示用的名称、图标、分类）、apps（已注册 MCP server 映射）、hooks（生命周期 hook 引用）。

子 agent 不走插件，走配置文件。~/.codex/config.toml（或项目级 .codex/config.toml）里：

[mcp_servers.my-server]
command = "node"
args = ["server.js"]

[agents.reviewer]
description = "Reviews code changes"
config_file = "agents/reviewer.toml"

项目指令走根目录的 AGENTS.md，Codex 每次运行前读它。

9 · Agent Plugins：跨厂商标准

Codex 的 plugin.json 开头是这个：

"$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json"

Agent Plugins 自称"开放、厂商中立的可复用组件打包标准"，目标是解决"各家 AI agent 客户端各搞一套插件格式"的碎片化。它定义：固定位置的目录结构（plugin.json + skills/ + mcp.json）、manifest 字段、以及两类组件——Agent Skills 和 MCP servers（stdio、Streamable HTTP、或旧的 HTTP+SSE）。各家的私有功能通过反向域名扩展命名空间挂上去，比如 OpenAI 的 extensions.com.openai。

初始技术指导委员会：Amazon、Cursor、Microsoft、OpenAI、Vercel。名单里没有 Anthropic。

这解释了两边的分叉：Codex 选择让插件能跨客户端复用，代价是组件类型要收敛到各家的公约数；Claude Code 选择把能力做到自己进程里，代价是这些东西天然不可移植——一个画 Claude Code 侧栏的 mod，换个客户端没有任何意义。

11 · 三个例子

例 1 · 把危险命令拦下来问一句（mod）

这是 blast-radius 那类 mod 的骨架：在 tool.call 上挂钩，命中危险模式就不放行，先用 $.ui.ask 问用户：

const RISKY = /\brm\s+-rf\b|\bgit\s+push\s+--force\b|\bDROP\s+TABLE\b/i

export function register(on) {
  on('tool.call', { tool: 'Bash' }, async ($, e, next) => {
    if (!RISKY.test(e.input?.command ?? '')) return next(e)

    const answer = await $.ui.ask({
      title: '这条命令可能不可逆',
      body: e.input.command,
      options: ['继续', '取消'],
    })
    // 取消就直接接管事件，工具根本不会运行
    if (answer !== '继续') return { deny: '用户取消了这条命令。' }
    return next(e)
  })
}

注意 { tool: 'Bash' } 这个 matcher——它让这个 hook 只在 Bash 调用上触发，别的工具连函数都不进。

例 2 · 把某一类请求换个模型跑（mod）

turn.step 在每一次发往模型的请求前触发，并且允许改 model 和 effort：

export function register(on) {
  on('turn.step', async function* ($, e, next) {
    // 上下文已经很满时，换一个上下文更大的模型
    const { context } = await $.session.usage()
    if (context.percent > 80) {
      return yield* next({ ...e, model: 'claude-opus-5' })
    }
    return yield* next(e)
  })
}
turn.step 和 process.spawn 的 hook 是 async generator（要写 function* 和 yield* next(e)），其余事件的 hook 是普通 async 函数。这是最容易写错的地方。

例 3 · 一个能同时给 Codex 和别家用的插件

team-review/
├── plugin.json
│   {
│     "$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
│     "name": "team-review",
│     "version": "1.0.0",
│     "description": "Our code review conventions and the PR tooling",
│     "extensions": {
│       "com.openai": {
│         "interface": { "displayName": "Team Review" }
│       }
│     }
│   }
├── mcp.json          # { "mcpServers": { "gh": { ... } } }

因为只用了标准里的 skills 和 MCP，任何实现了 Agent Plugins 的客户端都能加载它；OpenAI 专属的展示信息收在 extensions.com.openai 里，别家忽略即可。

12 · 怎么选

  • 只是想固化一段反复粘贴的指令 → skill。两家都支持，最便宜。
  • 要连外部系统 → MCP server。两家都支持，而且在 Agent Plugins 标准里，可移植。
  • 要强制一条每次都必须成立的规则 → hook，不要用 skill。skill 是 Claude "可以"读，hook 是"一定"跑。
  • 要界面、要拦截、要替换内置行为 → 只有 Claude Code mods 能做，而且放弃可移植性。
  • 要给整个团队发一套东西 → 如果团队同时用 Claude Code 和 Codex，把能放进标准的（skills + MCP）放进标准，各家专属的部分单独打包。
装之前先审。两边的插件都以你的权限运行。Claude Code 至少提供了 claude plugin validate 做安装前的静态能力清单——用它。
