→
Training

→
Difference

同一 token、同一模型参数

Actor 问题 1 · Linear

Linear 首次产生差异；actor 改用 SGLang 的 persistent GEMM

问题

相同 BF16 input 和 weight 经过 actor 的 F.linear 与实际 SGLang Engine 后，1,118,208 个 output 中有 224 个不同。差异随后被 ShortConv 传播。

Persistent GEMM 是什么？

SGLang deterministic inference 使用固定的 Triton GEMM kernel、tile 划分和 reduction order。Kernel 在执行期间保留工作 tile，因此称为 persistent GEMM。

固定调度可以避免 batch layout 改变最后几位浮点结果。

修改

Actor Linear 的 forward value 调用同一个 persistent GEMM；backward 仍沿原生 PyTorch graph 传播。没有全局替换所有 mm/addmm，避免 RoPE bmm 超过 AMD LDS 限制。

结果

Response 的 in_proj output 从 224 个不同元素降为 0，该 Linear boundary 达到 bitwise exact。

下一处差异移动到实际 Engine 使用的 ShortConv kernel。

Jobs 1908228 / 1908307 / 1908317。

ShortConv · backend 验证

Standalone 诊断与实际 SGLang Engine 使用不同 ShortConv backend

SGLang varlen ShortConv

Rollout 将多个不同长度序列压成一个 token buffer，并通过 seq_idx 标记序列边界。varlen kernel 在边界处重置 convolution state，避免不同序列互相读取历史 token。

问题

standalone process 中 _HAS_SGL_KERNEL=false，测试使用 Triton fallback；实际 SGLang Engine 使用 sgl_kernel causal conv。

实验设置与观察

固定相同的 B×x、BF16 conv weights 与 seq_idx。SGLang varlen kernel 精确复现实际 Engine output；HF standard conv 的 MAE 为 1.591e-5，共 118,795 个元素不同。

结论

Actor 使用同一个 varlen ShortConv kernel。再与 persistent GEMM 组合后，layers 0/1 的所有保存边界 bitwise exact。

Actor 问题 3 · RoPE

RoPE cache dtype 不同；统一为 BF16 后 post-RoPE Q/K exact

问题

Q/K/V projection 与 Q/K norm 已 exact；actor 和 SGLang 的 attention output 仍有差异。使用 actor 的 post-RoPE Q/K 时 attention MAE 为 1.077e-5；replay SGLang Q/K 后只剩 2.499e-7。

RoPE cache dtype 指什么？

RoPE 用预先计算的 cosine/sine cache 旋转 Q/K。SGLang 的 model-wide BF16 conversion 会把这份 cache 转成 BF16；actor 原路径保留了不同的 dtype boundary。

修改

Actor 在 RoPE 计算中也将 cosine/sine cache 转为 BF16，使旋转前的 Q/K、cache dtype 和乘加顺序与 SGLang 一致。

结果

Post-RoPE Q/K 达到 bitwise exact；layer-2 attention MAE 从 9.513e-6 降至 1.509e-6，下降 84.1%。剩余首差来自 attention kernel。

Jobs 1908494 / 1908579；切换 AITER/native RoPE backend 没有改变结果。

Actor 问题 4 · Attention kernel

输入 Q/K/V 已 exact；actor 改用同一个 unified Triton attention kernel

问题

Persistent GEMM 与 BF16 RoPE 使 Q/K/V exact 后，HF attention 与 SGLang attention 仍使用不同 kernel，softmax 和 value accumulation order 不同。

Unified attention 是什么？

Prefill、extend 与 one-token decode 使用同一套单阶段 Triton attention 实现，并提供相同的 prefix length、KV indices 和 mask。这里的 unified 指统一 kernel family 和 reduction contract。

修改

Actor attention forward 调用 SGLang 的 unified Triton kernel；先用保存的 exact Q/K/V 做 fixed-input replay，再接回完整 actor forward。

结果

Job 1908624 的 replay 与实际 Engine output bitwise exact；接回 actor 后，layer-2 attention output 与 out projection 都 exact。下一处首差移动到 RMSNorm reduction。

Actor 问题 7 · Expert MLP 与 weighted sum

Routes 已 exact；统一 expert GEMM、weighted sum 顺序和 BF16 output boundary

问题

TopK IDs 与 weights 已 exact，actor 的 expert F.linear 与 SGLang fused expert projection 仍有微小差异。Expert outputs 的合并顺序和最后一次 BF16 conversion 也不同。

Slot-ordered FP32 weighted sum 是什么？

每个 token 的 top-k experts 保留 router 返回的 slot 0→1→2→3 顺序。每个 expert output 先乘对应 weight，再按该顺序在 FP32 中逐项累加，最后转回 BF16。

修改

Expert projections 使用相同 persistent GEMM；weighted sum 保留原 slot order 和 FP32 accumulation；MoE block output 使用与 SGLang 相同的 BF16 boundary。

结果

每个 weighted per-slot expert output 达到 exact；layer-2 MoE output bitwise exact。Job 1908847 的 32-token chosen-logprob MAE 为 5.97e-7，max 为 1.55e-6；剩余首差位于 log-softmax。

FSDP backward · 问题与修改

Tied lm_head 的 FSDP 兼容性问题

问题

初始实现对所有 Linear 统一覆盖 forward。Transformer layers 可以 backward；与 token embedding 共享 weight 的 lm_head 触发 FSDP worker failure。

修改

  1. 保留 native Linear.forward，构造 FSDP 支持的 autograd graph。
  2. forward hook 计算 persistent-GEMM exact value。
  3. 使用 straight-through estimator 连接两者。
y = y_native + stopgrad(y_exact − y_native)

Straight-through estimator 使 forward 输出等于 y_exact，backward gradient 等于 y_native 的 gradient。Job 1910344 完成 backward/update；后续 captures 验证 FSDP forward 与 standalone exact actor bitwise equal。

最终原因

Q/K RMSNorm 与 residual-stream RMSNorm 的 dtype conversion 位置不同

Residual-stream norm

x_fp32 → normalize FP32 → keep FP32 → × FP32 scale

Attention Q/K norm

q_or_k_bf16 → normalize FP32 → cast to BF16 → × FP32 scale

此前全局保留 FP32 normalized activation；layers 0/1 exact，却在 layer 2 Q/K norm 首次产生 MAE 0.001218 / 0.001298。

Job 1911452。

最终修改

按 module 类型拆开 RMSNorm cast 规则

cast_normalized_to_input = ( norm.weight.numel() != model.config.hidden_size ) # residual norms: normalized stays FP32 # Q/K norms: normalized casts to input BF16 before scale

哪些修改有效？

Expert MLP · 控制变量实验

Expert GEMM 的 token dimension 是否造成主要误差？

问题与实验设置

在 expert Linear 的矩阵乘法中，M 表示一次送入该 expert 的 token rows 数量。full-sequence actor 的 M 通常大于 1；online decode 接近 M=1。

job 1907763 将 full-sequence actor 的 expert inputs 拆成单行，强制所有 expert GEMM 使用 M=1。

观察

  • logits MAE = 0.07871
  • P99 = 0.32813
  • max = 1.06250

三项误差均高于 route-ID replay 对照组。

结论：M dimension difference 无法单独解释当前误差。后续实验使用与 SGLang 相同的 persistent GEMM kernel，同时统一 tile 与 reduction order。

阶段 3 · 控制变量实验

Radix prefix cache 实验回答了什么问题？

机制

SGLang 用 radix tree 索引已计算的 token prefixes，并定位可以复用的 cache entries。新请求只计算最长匹配 prefix 之后新增的 tokens。

实验设置

Job 1907825 先建立可命中的 prefix cache，再提交只新增一个 token 的请求；随后将该 token 的结果与完整 prefill 结果比较。

观察

One-token extension 的 log-probability 与完整 prefill bitwise exact。

Extend kernel 负责在 cached prefix 后计算一段新增 tokens；本实验的新增长度为 1。

结论范围

该实验没有比较 prefix cache 开启与关闭，因此不支持“关闭 cache 可以提升精度”的结论。

结果只说明 cache-hit extension 与 full prefill 数值一致。

原始 online decode 使用 split decode attention kernel：先分别计算多个 KV partitions，再执行第二次 reduction。后续让 online decode 使用单阶段 unified extend kernel，消除了 SGLang 内部的 forward difference。
