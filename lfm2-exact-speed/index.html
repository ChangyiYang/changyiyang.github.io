保留路径

七个阶段把 3.15 ms/token 降到 1.38

① MoE + small-M

读取 gfx942 tuning；为 decode GEMM 选择小 M tile。

② Shape tuning

普通 projection 与 wide projection 使用不同配置。

③ K128 / stage2

扩大 K tile，同时满足 64-KiB LDS。

④ Native router

仅 2048→64 router shape 使用 native MM。

⑤ Fused combine

固定 slot order，删除 combine 中间 tensors。

⑥ Residual + norm

两阶段 exact kernel，保留 PyTorch rsqrt。

⑦ Delayed residual

跨 layer 延迟 FFN residual materialization。

候选 0 · Context length

先验证看起来最便宜的 KV-split 优化

观察

模型声明 128k context；deterministic split decode 据此 cap 到 256 splits，而 GSM8K 实际只需约 6–8。

修改

传 context_length=2048，只改变容量，不改变 active split reduction。

结果

generic deterministic 只变化约 1%；full exact unified decode 也无稳定收益。

决定

empty splits 不是主要成本；撤掉配置。

保留 5 · Native MM

只让一个已验证 shape 绕过 persistent GEMM

逐 shape screening

dense-up、down、lm-head 等 native mm.out 会改变数值，全部拒绝。

唯一 exact shape

未保留 · 扩大 native 范围

Fixed-M 与 classic hipBLAS 都没有成为 endpoint

Fixed-row M32

actor 拆 32 rows，decode pad 到 M32。全 shape exact，但 2.496 ms/token、15.466 s/step。

Router 58.6→999.4 µs；lm-head 2496.8→5174.1 µs。

Classic hipBLAS lm-head

局部切 backend 可 exact；20-step 5950e6tu 为 2.2376 ms/token，不优于 native-router endpoint。

固定 reduction path 的 padding 成本过高；两套 runtime code 均删除。

保留 6 · Ordered MoE combine

融合 combine，但不改变四个 expert slot 的加法顺序

out = bf16((((e₀·w₀)+(e₁·w₁))+(e₂·w₂))+(e₃·w₃))

原实现

多个 multiply/sum/cast operations，产生中间 tensors 与 launches。

新实现

Triton ordered_weighted_sum；固定 slot order、FP32 accumulation 与 BF16 cast boundary。

不能换 arbitrary reduction / atomic sum。exact 合同不仅是 FP32，还包括 slot order。

保留 7 · Residual + RMSNorm

每层 residual add 后马上做 RMSNorm

post_operator = operator_output + residual ffn_normed = rms_norm(post_operator)

Stage 1

FP32 residual add、square、相同 1024-wide ordered mean；同时输出 residual。

Stage 2

应用 inverse RMS 与 scale，保持 multiplication order。

rsqrt 留在 PyTorch：Triton rsqrt 与 1/sqrt 都会漂移 1 ULP。

保留 7 · 验证

为什么是两阶段，而不是更短的 one-kernel

Exact staged

rows 1–8192：normalized output、FP32 residual、inverse RMS 全 bitwise identical。

速度

decode rows 1.07–1.17×；prefill rows 1.92–2.35×。

One-kernel

inverse RMS max diff 5.96e-8；output max diff 1.91e-6。否决。

731ndh4e：49,424 warm tokens exact；1.7980 ms/token，12.4854 s/step。相对 fused combine，generation -10.3%，step -5.6%。

保留 8 · 跨层数据流

第二类 residual 不必在本层末尾 materialize

p = x + operator(norm(x)) m = FFN(norm(p)) y = p + m # 旧：写出完整 y next = operator(norm(y)) # 下一层：马上读回并 norm

y 在 layer 之间没有其他消费者，只被写到显存，再被下一层第一项 RMSNorm 读回。

传 pair (m, p)，下一层开头再精确计算 p + m 与 norm
保留 8 · 实现

跨层传两个已有 tensor，不改变数学顺序

Layer L

不算 y

residual=p

→
Layer L+1

normed,y = residual_add_rms_norm(m,p)

→
Final norm

同样消费 pair

最后一层也无需额外 materialize。

保持

  • FP32 p+m 顺序
  • cast / mean / rsqrt 合同
  • actor 仍用原 autograd 路径

删除

  • 逐层完整 y 写回
  • 下一层独立 norm launch
  • 最终 residual materialization

优化 exact inference 的四条经验

写清 operation order

FP32 不够；还要固定 slot order、cast boundary、reduction 与 rsqrt。

Shape screen → E2E

backend exactness 取决于 M/K/N 与 layout；局部快必须再过 Graph training。

优先删 materialization

最大收益来自 combine、residual/norm 与 delayed stream，而非小 kernel 微调。

负结果删除 surface

不保留无收益 flags、kernels 或 fallback branches。
