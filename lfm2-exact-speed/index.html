先解释对象

我们在对齐两次“同一个模型的前向计算”

Actor

训练侧前向

FSDP 把模型参数分散在多张 GPU 上；它重算回答中每个 token 的 log-prob，并参与反向传播。

↔
Rollout

生成侧前向

SGLang 逐 token 生成回答；它缓存历史状态，并为刚生成的 token 给出 log-prob。

chosen token：rollout 最终选中并写进回答、随后拿去训练的 token。我们只在这些真实训练位置比较两边的 log-prob。

先解释正确性

“Bitwise exact” 比“数值很接近”更严格

Bitwise exact

两个浮点数的二进制表示完全相同，不只是打印出来的小数接近。

Zero diff

每个 chosen token 的 actor log-prob 减 rollout log-prob 都等于 0。

MAE / Max

平均绝对误差 / 最大绝对误差；exact 时两者都必须为 0。

Pearson

两组数的线性相关系数；完全相同时为 1，但单独等于 1 还不代表 exact。

actor_logprob[token] === rollout_logprob[token]

BF16 用 16 bit 存一个浮点数，速度快但精度较低；FP32 用 32 bit，常用于中间累加。exact 要求两边在相同位置做相同的精度转换。

先解释速度

后面所有速度数字都落在这四个词里

Generation ms/token

rollout 生成阶段总耗时 ÷ 新生成 token 数；越低越快。

Whole step

一轮训练总时间：生成、旧 log-prob、actor 更新、权重同步等全部相加。

Warm step

去掉第 1 轮模型加载、编译和 Graph capture 后的稳态训练轮次。

Stock

当前主分支的默认快速实现；它是速度参照，但 actor/rollout 仍有数值差异。

先解释模型计算

一层里反复出现的六类操作

GEMM / MM

矩阵乘法，是 Linear、router 和 expert 计算的主体。

RoPE

把 token 的位置编码进 attention 的 Query / Key 向量。

RMSNorm

按向量均方根做归一化；rsqrt 就是计算 1/√x。

TopK / MoE

router 给 64 个 expert 打分，每个 token 只选分数最高的 4 个。

Attention

当前 token 的 Query 读取历史 token 的 Key / Value，决定应关注哪些历史位置。

Log-softmax

把模型最后的 logits 转成每个候选 token 的 log-prob。

先解释 Attention

KV split：把“全部历史”沿序列长度分块计算

KV cache

缓存历史

每个已生成 token 的 Key / Value 都留在显存里，下一步无需重新计算。

→
Split

分成若干段

例如 2,048 个历史位置切成约 6–8 段，每段独立算局部 attention。

→
Merge

固定顺序合并

再把各段的局部最大值、归一化和输出合成最终 attention 结果。

这里的 split 不是多 GPU，也不是把模型层切开；它只是在一张卡上把历史序列分段。

先解释运行方式

Microbenchmark、CUDA Graph 与 E2E 分别回答不同问题

Microbenchmark

只反复计时一个 GPU kernel（GPU 上执行的函数），用来筛选候选；不能证明整轮训练会更快。

CUDA Graph

先记录一串固定 GPU 操作，之后整串重放，减少 Python/CPU 每次重新发起 kernel 的开销。

E2E run

完整跑生成和训练，既看 chosen-token diff，也看 generation 与 whole-step；这是最终验收。

Eager 表示每次由 CPU 逐个发起 GPU 操作；它的 profiling 只能帮助定位，不能直接代替 Graph 下的最终时间。

先解释 Kernel 调优

M / N / K、tile、warp、stage 与 LDS 是什么

M × K · K × N

M 是本次 token 行数，K 是输入宽度，N 是输出宽度。decode 常见 M≤16，所以叫 small-M。

Tile / block

一个 GPU 程序一次计算的矩阵小块；M16/N64/K128 就是三条轴各自的小块尺寸。

Warp / stage

warp 是协作执行的一组线程；stage 是预取和计算流水线中同时保留的数据批次。

LDS / native MM

LDS 是一个计算单元内约 64 KiB 的高速共享存储；native MM 是直接调用 PyTorch/ROCm 默认矩阵乘实现。

gfx942 是 MI325X 所用 AMD GPU 架构的代码名；tuning table 是针对该架构预先测好的 kernel 参数表。

先解释结构词

Router、slot、combine、residual 与 materialize

Router / expert

router 是给 expert 打分的小矩阵；expert 是被选中后真正处理 token 的 FFN 子网络。

Top-k slot / combine

一个 token 的 4 个 expert 结果按第 1–4 个位置存放；combine 按权重把四路结果加回一个向量。

Residual

把某个子层输入直接加回输出的旁路；加法顺序会影响最后几个浮点位。

Materialize

把中间结果真正写成显存 tensor（多维数组）。delayed residual 是先保留两份已有数组，到下一层需要时再相加，少一次写回。

FP32 accumulation / BF16 cast boundary：先用 FP32 按固定顺序累加，再在指定位置转回 BF16；这两个细节共同决定 bitwise 结果。

候选 0 · Context length

候选 0：减少为 KV split 预留的最大分块数

观察

模型声明最长 128k token；系统因此最多预留 256 个历史分块。 这批 GSM8K 上下文只有约 2k token，实际通常只需 6–8 个分块。

修改

传 context_length=2048，把最大可预留分块数降到约 8；每一步仍只合并实际有内容的分块。

结果

只开通用确定性计算时，速度变化约 1%；完整 exact decode 也没有稳定收益。

决定

预留但没有内容的分块几乎不花时间；它不是主要成本，撤掉配置。

阶段 5 · Ordered MoE combine

融合 combine，但不改变四个 expert slot 的加法顺序

多个 multiply/sum/cast operations，产生中间 tensors 与 launches。

阶段 6 · Residual + RMSNorm

每层 residual add 后马上做 RMSNorm

post_operator = operator_output + residual ffn_normed = rms_norm(post_operator)

Stage 1

FP32 residual add、square、相同 1024-wide ordered mean；同时输出 residual。

Stage 2

应用 inverse RMS 与 scale，保持 multiplication order。

单独加入这一阶段：2.0041→1.7980 ms/token （generation -10.3%），13.2255→12.4854 s/step （step -5.6%）；49,424 warm tokens 保持 exact。

rsqrt 留在 PyTorch：Triton rsqrt 与 1/sqrt 都会漂移 1 ULP。

阶段 6 · 验证

为什么是两阶段，而不是更短的 one-kernel

Exact staged

rows 1–8192：normalized output、FP32 residual、inverse RMS 全 bitwise identical。

速度

decode rows 1.07–1.17×；prefill rows 1.92–2.35×。

One-kernel

inverse RMS max diff 5.96e-8；output max diff 1.91e-6。否决。

阶段 7 · 跨层数据流

第二类 residual 不必在本层末尾 materialize

p = x + operator(norm(x)) m = FFN(norm(p)) y = p + m # 旧：写出完整 y next = operator(norm(y)) # 下一层：马上读回并 norm

y 在 layer 之间没有其他消费者，只被写到显存，再被下一层第一项 RMSNorm 读回。

传 pair (m, p)，下一层开头再精确计算 p + m 与 norm

相对上一阶段：1.7980→1.3805 ms/token （generation -23.2%），12.4854→11.6351 s/step （step -6.8%）；55,224 warm tokens 保持 exact。
