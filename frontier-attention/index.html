01 / VERDICT & SCOPE

结论：行业不是选出一种 Attention，而是在组合三种记忆

截至 2026 年 9 月，四家前沿开源模型已经形成相当清楚的分工：递归状态承担便宜的连续记忆，稀疏检索负责从长历史中找候选，MLA/softmax 负责在候选上做精确内容寻址。所谓“新 attention”，真正的新意不在一个公式，而在三种记忆的比例和接口。

KIMI K3 · 93 LAYERS

69 KDA + 24 Gated MLA

KDA 用逐通道衰减的 delta-rule state；每个 block 的第四层用 NoPE MLA 恢复全局、逐 token 的内容访问。

QWEN3.8-FLASH-NEXT · 48 LAYERS

36 GDN + 12 QSA

GDN 用每 head 一个标量衰减；QSA 把历史压成 4-token micro-block，选 512 块后展开为 2,048 token。

DEEPSEEK V3.2 → V4.1

DSA over MLA

额外缓存一份窄 index key；lightning indexer 逐 token 选 top-2,048，core attention 仍是精确 MLA。

02 / BASELINES

先固定四个基线，否则所有“线性、稀疏、压缩”都会混成一团

A

标准 softmax attention：缓存每个 token 的 K/V，读取整段历史

scoret,s = qt⊤ks / √d　;　ot = Σs≤t softmax(scoret,:)svs

Decode 每来一个 token，要从 HBM 读一遍此前所有 KV。缓存是 O(L·dkv)，单步读取也是 O(L·dkv)；prefill 则是 O(L²d)。FlashAttention 改变 IO 路径，不改变“每个 query 看全部历史”这个语义。

B

MLA：压窄每个 token 的 KV，但 token 数没有减少

csKV = WDKVxs ∈ Rdc
Ks, Vs = up-project(csKV)　// cache latent c, not full per-head K/V

MLA 把每个位置的多头 K/V 压成一个共享 latent，再通过可吸收到 query/output projection 的矩阵恢复计算。它显著缩小 cache 宽度，但 cache 仍随 L 线性增长；如果不加 DSA，每个 query 仍读全部 L 个 latent。

C

Delta-rule linear attention：不保留 token，而是维护关联矩阵

êt = vt − S̃t−1⊤kt
St = S̃t−1 + βtktêt⊤　;　ot = St⊤qt

S 是一个 dk×dv 的 fast-weight associative memory。先问 state“这个 key 已经映射到什么 value”，再只写预测误差。缓存大小与 L 无关，但历史被压进有限维矩阵，不能保证任意旧 token 的精确随机访问。

D

Indexer-based sparse attention：历史还在，只把主 attention 的读取缩到 k

it,s = cheap_score(q̂t, k̂s)
𝒮t = TopK(it,:, k)　;　ot = ExactAttention(qt, K𝒮t, V𝒮t)

主 attention 从 O(L) 降到 O(k)，但 indexer 仍需判断哪些位置重要。DSA 用窄 token index；QSA/GLM-5.3 进一步先把历史按 4-token pool 压缩，减少 indexer 自己的扫描长度。

MLA 不是 linear attention它是低秩 KV 表示；每个 token 仍有 cache entry。
Sparse 不等于少存它主要减少读取和乘加；被索引的历史通常仍需保存。
AttnRes / mHC 不是 token attention它们在网络深度轴组织 residual stream，不能拿来替代 KDA/DSA。
03 / KIMI K3

KDA：先忘、再纠错、最后读取

Kimi Linear 给出 KDA；Kimi K3 修改 decay 参数化和 kernel 路径，并用 3:1 KDA/Gated-MLA 扩到 93 层、1M context。

K

KDA 的核心不是“RNN 化”三个字，而是对 fast-weight 矩阵做一次有明确含义的在线回归更新。对单个 head，state St∈Rdk×dv 表示从 key space 到 value space 的暂时映射。

Block pattern3 : 1 + final MLA
KDA stated_k × d_v / head
Decay lower boundg_min = −5

KDA-1

一次 decode update 的完整五步

// ① channel-wise decay
S̃t−1 = Diag(αt) St−1

// ② read existing association at current key
v̂t = S̃t−1⊤ kt

// ③ residual error; ④ rank-1 corrective write
et = vt − v̂t
St = S̃t−1 + βt kt et⊤

// ⑤ query the updated state
õt = St⊤ qt

把第 ②–④ 步展开，就得到论文的等价式：

St = (I − βtktkt⊤) Diag(αt)St−1 + βtktvt⊤
Decay 不是一个 head 一个数

αt∈(0,1)dk，state 的每个 key channel 有独立 retention。GDN 的 αt 是 scalar；这就是 KDA 比 GDN 更细的地方。

Delta rule 不盲目累加

普通 linear attention 写 ktvt⊤，相似 key 会持续叠加并互相污染；KDA 只写 v − S̃⊤k，重复 key 会纠正已有映射。

β 是写入步长

βt=sigmoid(Wβxt)。β≈0 时几乎不改 state；β≈1 时强力把当前 key 的映射拉向 vt。

q/k 不是裸 projection

q、k、v 先过 depthwise causal ShortConv 与 Swish；q/k 再做 L2Norm，限制 rank-1 transition 的谱，避免 state 爆炸。

输出还有一层内容 gate

yt=Wo[sigmoid(Wgxt)⊙RMSNorm(õt)]。K3 从 Kimi Linear 的低秩 gate 改为 full-rank gate。

KDA-2

为什么训练时不是逐 token for-loop：chunkwise UT/WY 形式

Decode 可以直接 recurrent update；训练/prefill 若逐 token 扫描则 GPU 利用率很差。KDA 把长度 L 切成大小 C 的 chunk：chunk 之间递归，chunk 内把一串 rank-1 transition 压成 dense matrix 运算。

S[c+1] = Diag(γ[c]C)S[c] + (Γ[c]⊙K[c])⊤(U[c] − W[c]S[c])

O[c] = (Γ[c]⊙Q[c])S[c] + Tril((Γ⊙Q)(K/Γ)⊤)(U−WS)

第一项读前面所有 chunk 压成的 incoming state；第二项计算当前 chunk 内的 causal interaction。U/W 来自 UT transform，把序列 rank-1 updates 变成 Tensor Core 友好的矩阵乘。Kimi Linear 给出的单 head FLOPs 是 6Tdh² + 3TCdh + TC²，而 full attention 主项是 2T²dh。

K3 CHANGE

K3 为什么把 log-decay 限制在 (−5, 0)

KIMI LINEAR

g=−exp(A)·softplus(z)，下界是 −∞。chunk 内需要除累计 retention Γ；1/Γ 可能溢出，因此 diagonal tile 需显式 position-pair 计算。

KIMI K3

g=−5·sigmoid(exp(A)z)，α=exp(g)。16-token tile 的累计 log-decay 大于 −80，1/Γ 留在 BF16 动态范围，diagonal/off-diagonal tile 都能走 dense Tensor Core GEMM。

gt,j = gmin·sigmoid(exp(Ah)zt,j) ∈ (−5,0)
αt,j = exp(gt,j) ∈ (e−5,1)
GLOBAL PATH

Gated MLA 在 3:1 hybrid 中到底补什么

KDA 的 state 是固定容量，擅长统计、连续状态和反复更新，但无法保证从一百万 token 中精确复制任意一次出现。于是每三层 KDA 插一层 MLA。MLA 为每个 token 缓存低维 latent cs，仍能做全局 token-to-token softmax；K3 的 MLA 完全使用 NoPE，把位置/近因偏置交给相邻 KDA，并在 MLA 输出上加 full-rank channel gate。

SERVING

推理侧不是只有“KV 少 75%”

  • Decode：KDA 每层只维护一个 dk×dv/head state，单步成本不随 L 增长；MLA 层仍随 L 读 cache。
  • Context parallel：KDA segment 不能只算 S=0 的局部 state 再相加。每段必须产出 affine fragment (M, S̃)，用结合律做 prefix scan；K3 的 KCP 用一次 fixed-size all-gather 交换两者。
  • Prefix cache：命中 MLA 前缀还不够，命中边界必须有对应 KDA state checkpoint。K3 将细粒度 hash block 与粗粒度 physical page 解耦，只在可复用端点稀疏保存 state。
  • Cache manager：MLA 是 per-token pages，KDA 是 per-request state；K3 把两类对象放进同一 byte-size page pool，统一 allocation/refcount/eviction。
一句话判断：KDA 是四家里对“常数状态线性注意力”解释、训练 kernel、跨卡 CP 和 serving cache 都公开得最完整的一条路线；它的代价不是 recall 完全免费，而是必须保留周期性 global MLA，并让推理引擎真正理解两种 cache。
04 / QWEN3.8-FLASH-NEXT

GDN 压缩连续历史，QSA 按 micro-block 找回离散证据

Qwen 的关键不是单个 QSA，而是把“3 个 GDN + 1 个 QSA”做成可重复的 token-mixing block。

Q

Qwen 的 linear path 是 Gated DeltaNet。它和 KDA 共用 delta rule，但忘记机制更粗：每个 head、每个 token 只有一个 scalar α，而不是 KDA 的 dk 维 vector。

GDN

GDN 的 erase-and-write recurrence

S̃t−1 = αtSt−1
et = vt − S̃t−1⊤kt
St = S̃t−1 + βtktet⊤
yt = St⊤qt

αt=exp[−exp(A)·softplus(Wαxt+bα)] 控制整个 head 的 memory lifetime，βt=σ(Wβxt) 控制写强度。q/k/v 同样经过 ShortConv；q/k L2-normalize；输出是 Wo[σ(Wzx)⊙RMSNorm(y)]。Qwen 的改动之一是把原 GDN 的 SiLU output gate 换成 bounded sigmoid。

KDA vs GDNKDA 的 αt,j 能让某些 key channel 长记、某些快忘；GDN 的 αt 对整个 head 一起衰减。KDA 更有表达力，GDN 的 recurrence 与 kernel 更简单。
QSA-1

Indexer 先把 4 个 token 压成一个 block key

轻量 projection

每个 query token 产生 H=4 个 index query：q̂ih=RMSNorm(WQhxi)；历史每个 token 只产生一个共享 index key kj=WKxj。这是 4Q×1KV 的 MQA indexer。

先 average-pool，再加位置

把不重叠的 r=4 个 key 做平均：k̂b=RMSNorm(AvgPool(k4b:4b+3))。池化发生在 RoPE 之前，避免把不同 rotary phase 的向量直接平均。

partial RoPE

128 维 index head 中只有 64 维做 RoPE。query 保留位置 i；block key 使用块起点 pb=4b。一个 block 因此只有一个内容摘要和一个块级位置。

block-causal score

只有整个 block 已经位于 query 之前时才可选；未完整可见的 block score 为 −∞。

Ii,b = Σh=1..4 ReLU(⟨qih, k̄b⟩),　if 4b+3 ≤ i
Bi = TopK⌈2048/4⌉=512({Ii,b})
QSA-2

选的是 block，真正算 softmax 时仍回到完整 token

TopK 返回最多 512 个 block。QSA 把每个 block 展开回原始 4 个 token，截断到 K=2,048；当前尚未凑满 4 个 token 的 tail block 不参加 indexer，但它的可见 token 被无条件加入集合。然后 core GQA 用完整 q/k/v 在这些原始 token 上计算真正的 softmax attention。

Block sparse 的实际偏差是什么？

如果一个重要 token 所在 block 的平均表示不显著，整个 block 都可能漏掉；反过来，一个 token 拉高 block 分数后，其余三个普通 token 也被读入。这是用 4× indexer 降本换来的召回粒度。Qwen 的 ablation 显示 r=4 是质量/延迟平衡点，而 r=8/16 更便宜但 retrieval 下降。

TRAINING

QSA 不能插上就用：先蒸馏 indexer，再让 backbone 适应 sparse mask

STAGE 1 · DENSE DISTILLATION

保留 full attention。把 teacher 各 head 的 softmax distribution 求和并 L1 normalize；对每 4-token block 做 max-pool，保留块内最显著 token；以 KL 训练 indexer。1,000 steps，约 2B tokens。

STAGE 2 · SPARSE TRAINING

启用 top-block mask，backbone 与 indexer 联合训练。KL 只在被选 blocks 内计算，teacher probability 重新归一化。8,000 steps，约 200B tokens。

为什么 teacher 聚合用 max-pool，而 index key 用 avg-pool？前者是监督信号，要防止重要单 token 被块平均稀释；后者是实际索引表示，要保持平滑稳定并便于 kernel。

PREFILL INDEXERO(L²/r)r=4，不是线性；只是把 key 轴缩短 4×。
PREFILL COREO(LK)K=2,048，替代 full GQA 的 O(L²)。
DECODEO(L/r + K)先扫 L/4 blocks，再读最多 2,048 token。

论文报告的是 attention module kernel-level 数据：1M context 下 prefill 7.6×、decode 4.9×，包含 indexer 与 sparse core，但不是整模型端到端加速。多步 MTP 可复用 top-k indices，避免每个 draft step 重跑 selector。

一句话判断：QSA 的技术核心不是“稀疏”二字，而是把 DSA 的 token indexer 改造成硬件更规整的 block indexer，同时用两阶段训练让模型学会这套有损候选生成。
05 / DEEPSEEK DSA

DSA：用窄 index cache 筛选宽 latent KV cache

DSA 没有 linear recurrence。它保留每个 token 的 MLA latent，用另一套更便宜的 index representation 决定本次只读哪 2,048 个。

D

要理解 DSA，必须先理解它是在 MLA 的 MQA decode 形式上实例化的：selection 发生在 token latent cs 之前；所有 query heads 共享同一组被选 token，才能让 sparse gather 和 kernel 有足够复用。

MLA

主 cache 到底存什么

q residual 1536latent KV cs 512shared RoPE key 64per-head qnope 128per-head value 128

每个历史 token 缓存 csKV∈R512 和共享的 ksR∈R64，而不是 64 份完整 K/V。Decode 时，WUK 可以吸收到 query 一侧：qnope 先变换到 latent 维，与 cs 直接点积；softmax 后得到 latent 加权和，再通过 WUV 产生各 head 输出。这样被选 token 的 latent 一次读取可服务全部 query heads。

scoret,s,h = ⟨q′t,h, csKV⟩ + ⟨qt,hR, ksR⟩
zt,h = Σs∈𝒮t softmax(scoret,𝒮t,h)s csKV
ot,h = WhUV zt,h
INDEXER

Lightning indexer 的精确打分式

It,s = Σj=1..HI wt,jI · ReLU((qt,jI)⊤ksI)
𝒮t = {s | It,s ∈ TopK(It,:, 2048)}
Query 端

复用 MLA 的 q low-rank residual，经 WqI 产生 HI=64 个 128 维 index queries；同一个 hidden state 还产生 64 个 learned scalar weights wt,jI。

Key 端

每个历史 token 另存一个共享 128 维 index key ksI。官方参考实现对 q/k 做 Hadamard rotation 并以 FP8 缓存 index key 与 scale。

非负匹配后加权合头

每个 index head 的 dot product 先 ReLU；随后乘 query-dependent wt,j 再跨 head 求和，得到所有主 attention heads 共用的一份 token ranking。

TopK 后才进入 MLA

选出的 2,048 个位置用于构造 sparse mask；主 attention 对这些位置运行真正的 MLA softmax，不直接把 index score 当 attention weight。

为什么 ReLU论文明确给出的理由是 throughput。Indexer 的职责是排序而不是概率建模；ReLU 比 softmax/复杂 kernel 更容易 FP8 化和融合。
TRAINING

Indexer 的监督来自主 attention，而不是语言模型 loss

DENSE WARM-UP

主模型冻结，仍跑 dense MLA。把主 attention 各 head 分数求和、沿序列 L1 normalize 成 teacher pt,:；最小化 KL(p || softmax(I))。1,000 steps × 16 × 128K，约 2.1B tokens。

SPARSE TRAINING

启用 top-2,048，并训练全模型 15,000 steps，约 943.7B tokens。Indexer 输入从主图 detach；indexer 只收 KL gradient，backbone 只收 LM loss，防止 selector 与主干通过捷径共同漂移。

COST

DSA 把最贵的 O(L²) 换成两个不等价的部分

LIGHTNING INDEXERO(L²dI) prefill仍是 dense token-to-token 打分，但 dI 小、FP8、heads 少。
CORE ATTENTIONO(Lk·d)k=2,048，替代 MLA 的 O(L²d)。
DECODE CACHE READO(LdI + kdc)扫窄 index K，再 gather 2,048 个 latent KV。

因此 DSA 的瓶颈会从 dense MLA 迁移到三件事：index logits、TopK、以及对 latent KV 的不规则 gather。DeepGEMM/DeepSelect 专门优化前两者，FlashMLA 承担 sparse core。TopK indices 在 TP ranks 间必须一致；参考实现由 rank 0 广播并断言一致。

实现陷阱：DSA indexer 的 RoPE 使用 non-interleaved layout，而 MLA 的 RoPE 使用 interleaved layout。DeepSeek 官方 2025-11-17 专门修复过参考实现中的这一差异；这不是可忽略的格式细节，错了会直接损伤模型质量。
一句话判断：DSA 是对既有 MLA 系统侵入最小的稀疏化：不改 cache 的语义，只增加一个 selector 和 sparse core；但它省掉的是“宽 attention 读全历史”，并没有消灭逐 token 历史，也没有让 indexer 的长度依赖消失。
06 / GLM-5.3-FLASH

GLM 的机制不是简单相加：KDA + pooled DSA + NoPE MLA

5.3-Flash 的公开配置与 Transformers 实现给出了完整 layer schedule 和 index pooling；它已经不是 GLM-5.2 的 IndexShare 配方。

G

45 层按 [KDA, KDA, KDA, DSA] 重复，最后以 KDA 收尾：34 个 linear-attention 层，11 个 sparse-attention 层。KDA 负责位置敏感的连续状态，DSA 负责精确内容检索。

LINEAR

GLM 的 KDA 几乎按 K3 的工程版实例化

每层先把 q/k/v 三个 projection 拼接，过 kernel size=4 的 depthwise causal conv 和 SiLU；forget gate 是 hidden→128→64×128 的低秩 projection，产生逐 channel log-decay；β 是每 head 一个 scalar；q/k 在 KDA kernel 内 L2-normalize。

g = −5·sigmoid(exp(Ah)·(WbWax + dt_bias))
α = exp(g)
St = (I−βtktkt⊤)Diag(αt)St−1 + βtktvt⊤

同样的 −5 lower bound 意味着它继承了 K3 的数值动机：限制 cumulative reciprocal，允许 chunk KDA 的 causal tiles 使用半精度 dense matmul。Decode 调 fused recurrent KDA；prefill 调 chunk KDA；reference Transformers 把最终 recurrent state 转成 FP32 存入 cache。

具体 state 账64×128×128=1,048,576 个数/linear layer。按参考实现 FP32 是约 4 MiB/层、34 层约 136 MiB/request，且不随 context length 增长；实际生产 kernel 可能采用不同 state dtype，但固定容量并不等于“state 很小”。
SPARSE

GLM 的 DSA 不是 DeepSeek 原版：先做可学习的 4-token 逐通道池化

生成 token index key 与 compression logits

每个 token 产生 128 维 index key kj，以及另一条 128 维 gate score aj。每个 pool offset 还有一个可学习位置偏置 er∈R128。

逐 channel 学习如何聚合 4 个 token

对 pool b 内四个 token，在 token 维做 softmax(aj+eoffset(j))；每个 key channel 都有不同权重。pool key 是四个 kj 的逐通道加权和，不是 QSA 的简单 AvgPool。

32-head index score

query 端用 MLA 的 q residual 产生 32×128 index queries。与 pooled key 点积、ReLU，再用 hidden state 产生的 32 个权重合头，延续 DSA 的 scoring 形式。

选 512 pools，展开成 2,048 token

index_topk/index_kpool=2048/4=512。被选 pools 展平回 raw indices；当前未满 4 token 的可见 tail 无条件 append，最多再加 3 个位置。

NOPE

为什么 GLM 的公开配置把 qk_rope_head_dim 设成 0

GLM-5.3-Flash 的 DSA core 配置是 qk_nope_head_dim=256、qk_rope_head_dim=0，且 mla_use_nope=true；indexer 同样没有 rotary 子维。换言之，global sparse layers 完全按内容匹配，位置信息由前三个 KDA 层的 decay、ShortConv 和 recurrent dynamics 注入。这个设计与 Kimi K3 的 NoPE MLA 思路一致，但与 Qwen QSA 的 64/128 partial RoPE 相反。

5.2 → 5.3

IndexShare 和 pooled DSA 不要混为一谈

GLM-5.2 · INDEXSHARE

跨相邻 sparse layers 复用同一 top-k index，减少重复 selector；官方称 1M context 每 token FLOPs 下降 2.9×。风险是不同层想看的 token 未必一致。

GLM-5.3-FLASH · K-POOL

当前公开 config 的 indexer_types 全为 full：每个 DSA 层自己索引，但层内先把 4 token 压成 1 pool。它用 intra-layer compression 换成本，不依赖 cross-layer similarity。

DEPTH

mHC 是配套 residual 机制，不是第五种 attention

模型维护 4 条 residual streams。每个 sublayer 前，pre weights 把四条流 collapse 成输入；sublayer 输出由 post gate 写回各流；stream 间 mixing matrix 经多轮 Sinkhorn 归一化，约束为近似 doubly-stochastic。它改善深度方向的信息传递和训练稳定性，但不会减少 token cache 或改变 DSA/KDA 的时间复杂度。

一句话判断：GLM-5.3-Flash 是当前四家里最像“最终工程配方”的实现：KDA 解决大多数层的长度增长，pooled DSA 解决少数 global 层的 indexer 成本，NoPE 把位置责任统一交给 KDA；代价是 serving 同时背负 recurrent state、latent KV、pooled index 和四路 residual。

哪个“最好”？要先指定瓶颈

HBM capacity / 超长 decode：KDA/GDN 的固定 state 最直接；KDA 表达力更细，GDN 更简单。
精确 needle retrieval：token-level DSA 粒度最细；QSA/GLM pooling 更快但引入 block recall 风险。
已有 MLA 系统迁移：DSA 改动最局部。
1M context 的整机成本：3:1 linear+sparse hybrid 最有潜力，因为它同时减少“多少层存 KV”和“这些层每步读多少 KV”。

08 / INFERENCE TAKEAWAYS

站在推理 Infra 侧，真正要记的 8 件事

  1. 3:1 hybrid 减少的是有 per-token KV 的层数。“KV 下降最多 75%”来自层比例；第四层依然有 cache，不能把它宣传成整模型 constant memory。
  2. KDA/GDN state 固定，但可能很宽。state 是每 head 的矩阵而非一个 vector；GLM reference 的 KDA state 约 4 MiB/层/request（FP32）。短上下文未必比 KV 更省。
  3. Linear prefill 与 decode 是两套 kernel。Prefill 需要 chunkwise UT/WY 或 parallel scan；decode 用 recurrent update。只优化其中一个，端到端仍可能输给 FlashAttention。
  4. Sparse 的总成本是 index + TopK + gather + core。只报 core attention 的 O(LK) 没意义；DSA 的 indexer 仍是 token dense，QSA/GLM 才进一步把候选轴压成 L/4。
  5. Block index 用吞吐换粒度。连续 4-token gather 对 GPU 友好，也把一次错误选择放大成整块。训练必须让 indexer 和 backbone 一起适应这个偏差。
  6. DCP 不能原样套到 recurrent state。Softmax KV 可按位置分片后用 log-sum-exp 合并；KDA segment 是 affine transform，必须交换 (M,S̃) 并做 prefix composition。
  7. Prefix cache 命中条件变成双重一致。Hybrid 模型既要 MLA/QSA/DSA 的 token cache 命中，也要命中边界处的 linear state checkpoint，否则仍要从更早位置重算。
  8. Scheduler 必须是 layer-type aware。KDA recurrent、chunk KDA、indexer、TopK、sparse MLA/GQA 与 dense fallback 的 batch shape 都不同；把它们统一当 FlashAttention 调度会丢掉架构收益。
如果只押一个总方向：不是 KDA、QSA 或 DSA 单独胜出，而是 linear state 承担 75% 层、pooled sparse attention 承担 25% 层；下一轮竞争会发生在 state 精度、index recall 和统一 cache manager，而不是再发明一个 attention 缩写。
