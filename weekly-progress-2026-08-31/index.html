01Enabled

02Bounded

DSpark performance now has a product boundary

The AMD hybrid path reduced a speculative step by 16.4%. Repeated concurrency sweeps showed the gain is real for a single low-latency stream, but disappears at concurrency two and degrades further for batched rollout.

~1.15× at c=1use DSpark for single-stream latency; disable it for high-concurrency rollout
03Delivered

Draft-training corpus generation completed

A 25-node B300 collection run regenerated the Open-PerfectBlend corpus with the 24B always-think target. Dynamic response caps avoided known-wasted generation while preserving every raw row and its audit fields.

1,420,909 rows22,225 readable Parquet files · 1,200,199 training candidates · 84.47% keep rate
04Reproduced

The AMD–B300 acceptance gap is stable

A shared GitHub harness pinned prompts, token IDs, model files, sampling, request order, cache state, and server identity. Three independent boots per platform produced exactly the same integer counts within each platform.

4.080 vs 4.582 ALAMD remained 10.96% lower after controllable factors were aligned
05Finding

Numerical differences were isolated—not overclaimed

Frozen-input replay proved that the exact AITER CK stage-2 operator is not bitwise deterministic. Separately, matched effective-BF16 target rescoring found systematic AMD/AITER versus B300/FlashInfer token differences. Neither result alone proves the direction of the AL gap.

16.11% top-1 mismatchteacher-forced target positions; deterministic within each platform, causal attribution still open
06Validated

Training and product evaluation moved beyond microbenchmarks

A symmetric 2×2 continuation study found no stable directional quality shift between the stacks at the measured endpoint, while B300 trained materially faster. The full 150-task ClawEnv loop also showed that DSpark improves token throughput even when longer natural trajectories reduce tasks per second.

1.269× token throughputcanonical DSpark versus no-spec in the complete VERL agent loop

Bottom line

We now have a working B300 stack, a production-scale draft corpus, a reproducible cross-platform gap, and evaluation that separates kernel speed from real agent behavior. The next decisions can be made from measured boundaries rather than one-off runs.
